# K8s Systems Design — 改版约定

2026-11-05 经用户确认：以 Protocol Explorer 为视觉与交互参考，采用蓝白工程图、组件分组拓扑与紧凑学习工作区；页头左上角及页签采用官方 Kubernetes 舵轮 Logo。

面向具备 Linux、容器基础的开发者和初级运维，用中文解释 Kubernetes 的基础、应用与运维。静态站点，不连接真实集群；所有操作示例由学习者自行在实验环境执行。初始改版阶段只修改和验证本地代码；2026-11-05 用户明确授权本轮上传并部署，按现有 GitHub Pages 工作流提交、推送与核验。

## 内容与图解

保留三条路径、27 个主题、54 个独立场景，以及搜索、知识图谱、深浅主题、进度、示例下载和官方来源。

解除四参与者、四阶段限制。当前主流程包含 6–9 个逻辑参与者、6–12 个阶段，共 305 个阶段（含局部故障场景）。架构图区分 kubectl、API Server、etcd、Deployment 控制器、ReplicaSet 控制器、调度器、kubelet、容器运行时与 Pod。其余主题按机制展开额外角色，不将实际流程压缩成同一套四盒子。

参与者按组件职责或资源角色分组。背景线表达场景关系上下文，当前线表达本阶段关系。拓扑与时序视图、阶段导航、执行轨迹共享一个播放进度。点击组件查看关联阶段，点击时序消息或轨迹定位阶段；画布可展开，窄屏横向浏览。

动效解释请求与数据传递、控制信号、内部检查以及 Pod 待创建／运行／就绪／退出。滚动更新明确新旧副本切换，控制循环明确新 UID 的替代 Pod，HPA 明确更新 scale 后由工作负载控制器创建副本。支持暂停、倍速和减少动态效果。

控制器、调度器和 kubelet 通过 API 协作；etcd 为持久化后端。业务请求不逐跳经过 API Server 或 EndpointSlice 对象。阶段压缩异步观察和控制循环，不表示真实耗时或严格全局顺序。故障场景保持独立前提，允许少量参与者解释局部失败。

## 官方组件图案

根据用户补充，流程参与者改为官方组件／资源符号。原版 SVG 从 Kubernetes community/icons 本地提供，保持 artwork 不变；终端、容器运行时、DNS、指标、检查与声明等辅助角色使用独立线框图形。控制器与受管资源分别匹配图标。通用 Service 数据面不套用 kube-proxy 图标；Pod 安全准入不使用已移除的 PSP 图案。EndpointSlice 复用端点符号族，仍以准确的资源名称说明。图案在拓扑与时序视图保持一致。

## 等距立体效果

用户进一步要求流程画面接近 Protocol Explorer 的轻 3D 风格。拓扑采用可复用的 SVG 等距模型：终端、服务器机柜、节点代理、堆叠存储、Pod 容器舱、容器运行时、副本集合、控制台、调度台、路由器、DNS 球体、检查屏幕、叠层文档、安全盾牌与命名空间围栏。顶部、正面和侧面有不同明暗，配落地阴影、端口与细节描边；悬停或当前组件轻微抬升。原版官方符号保留为识别徽标，源文件不修改。时序表头保持平面符号，避免小尺寸立体模型降低识别度。所有模型仍代表逻辑角色，不据小立方体数量推断真实资源数量。

画布不常驻展示“等距立体模型 · 保留官方识别图标”等造型说明，以减少视觉杂项；组件说明区域仅在选中参与者时出现，关闭选择后收起并释放空间。

以“运行一个网站”为连贯例子，按镜像与容器回顾 → 为什么需要 Kubernetes → 集群与节点 → Pod → Deployment → Service → 扩容和故障恢复的小体验展开。每屏聚焦一个问题，约 8–10 分钟（阅读与交互时间估计），复用轻 3D 图案，保持深浅主题和移动端可读。介绍声明目标、控制器协调、新 Pod 身份和就绪检查，不暗示即时恢复或服务永不中断。安装集群与进阶内容使用后续实践入口。

教学次序参考极客时间《深入剖析 Kubernetes》的公开课程目录；概念事实核对 Kubernetes 官方文档，正文与图解为本站原创整理。参考目录：https://time.geekbang.org/column/116；官方入门：https://kubernetes.io/zh-cn/docs/tutorials/kubernetes-basics/。本轮先本地实现与验证，未包含新一次发布授权。
