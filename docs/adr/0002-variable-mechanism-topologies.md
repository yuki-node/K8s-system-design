# 用场景拓扑取代固定四参与者模型

日期：2026-11-05。状态：已接受。替代 0001 中关于四个参与者、四个阶段的限制；离线教学边界继续适用。

用户确认沿用 Protocol Explorer 的蓝白工程图与等距视觉，采用官方 Kubernetes Logo，并增加内容深度与教学动效。原模型把全部主题压进四个参与者、四个阶段，合并 API Server / etcd 等角色，隐藏控制循环和工作负载变化。

参与者和阶段改为可变长集合，各场景独立定义分组与状态里程碑。拓扑展示整个关系上下文，时序视图展示逐步交互，两者与同一个播放状态及事件表联动。数据传输、控制信号、内部处理与失败使用不同的视觉语义；组件仍通过 API 协作，不把 etcd 画成调度器的调用来源。

代价是课程作者需要维护更多角色、分组与状态，布局也要处理不同规模及移动端横向浏览。保留原四参与者故障场景作为合理的局部诊断，不为数量而添加无关组件。运行时保持纯静态，不引入真实集群连接。
